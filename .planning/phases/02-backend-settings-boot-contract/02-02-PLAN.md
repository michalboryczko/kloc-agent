<objective>
ISS-07: extend the Pydantic `Settings` validator so the combination
`allow_hmac_fallback=True` AND `kloc_hook_secret == "dev-secret-please-rotate"`
AND `stub_mode=False` raises at boot. Per D-05..D-08 the check lives in the
same `model_validator(mode="after")` family as the existing provider-key
validator and the default `kloc_hook_secret` value stays as-is.

Purpose: prevent the production-shaped boot path where an operator has opted
into HMAC fallback (a legitimate dev flag) but forgot to rotate the placeholder
shared secret. With both true, any caller who learned the well-known
`"dev-secret-please-rotate"` could forge signed webhooks against the runner
inbox.

Output:
- `Settings` validator extended with the new 3-AND check.
- Regression tests in `tests/unit/test_settings.py` covering the full truth
  table (raise / pass cases).
- `tests/unit/test_webhooks_hmac_fallback.py` updated so its `_build_app` keeps
  passing under the stricter validator (existing tests already pass
  `stub_mode=True`, but pin the contract).
</objective>
