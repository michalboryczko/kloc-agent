<objective>
Fix ISS-06 (Medium): in `runner/channel.py:_stream_outbound`, on a transport exception the `except` branch drains `_outbound` via `get_nowait` into `pending_after_break` for the next attempt. But events that `body_iter` already yielded and that httpx had not yet flushed across the TCP boundary are lost — they are gone from `_outbound` (already pulled by the iterator) and never re-yielded. This is exactly the path that produces "missing `RUN_FINISHED`" symptoms when the backend resets mid-emit.

Fix: track the most recently yielded frame in a local `last_inflight: dict | None`. Inside `body_iter`, update `last_inflight = event` immediately before yielding the encoded line. On reconnect (entering the new stream attempt or after the `except`), prepend `last_inflight` to `pending_after_break` before/along with draining `_outbound`, then clear it. A frame that was successfully acked is over-sent at most once on the next reconnect — duplication is preferable to silent loss; the backend already tolerates duplicate AG-UI frames (the execution-ring `seq` is server-assigned, and the dispatcher's run-id routing is idempotent on intermediates).

Purpose: closes the transport-loss path that swallows `RUN_FINISHED`, which manifests as test-failure "Issue 4 — vertical-slice RUN_FINISHED missing" in the QA failure cluster.
Output: corrected `_stream_outbound` reconnect path + regression test exercising the mid-emit transport reset.
</objective>

    In `runner/channel.py:_stream_outbound`, restructure the reconnect loop so a single `last_inflight: dict | None` is tracked across reconnect attempts. Required structural changes (directive prose — no code blocks):

    - Declare `last_inflight: dict | None = None` in the function scope of `_stream_outbound`, BEFORE the `pending_after_break` declaration so both are visible to `body_iter` via closure.
    - In `body_iter`, immediately before `yield line` (for each event pulled from `_outbound`), set `last_inflight = event` via `nonlocal last_inflight`. The assignment happens BEFORE the encode-to-bytes is irrelevant — what matters is that `last_inflight` reflects the most recent event handed to httpx.     - Actually, simpler shape: in `body_iter`, BOTH the pending_after_break replay loop AND the main `_outbound` loop must set `last_inflight = event` before yielding. This ensures a failure during replay of a previously-buffered frame still re-replays that frame on the next attempt. Use `nonlocal last_inflight` to allow assignment inside the nested generator.
    - In the `except Exception` branch of the outer `try` (after `log.exception("channel.outbound_failed; reconnecting")`), BEFORE the existing `while True: _outbound.get_nowait()` drain loop: if `last_inflight is not None`, append it to `pending_after_break` and set `last_inflight = None`. Then do the existing queue drain (which appends `_outbound` contents AFTER the in-flight frame). The order matters: in-flight first, then queued.
    - The next stream attempt's `body_iter` will read `pending_after_break` first (existing behaviour) and re-yield E1 ahead of the drained queue events.
    - On a clean exit (sentinel seen via `sentinel_seen = True; return`), do not touch `last_inflight` — the function returns and the reference is dropped.
    - On the `4xx/5xx` `continue` path (response.status_code >= 400 at line 185), the `async with` block exited cleanly and `body_iter` was never iterated to completion. `last_inflight` may or may not be set depending on whether body_iter yielded anything. For correctness, on that `continue` also append `last_inflight` to `pending_after_break` if non-None and clear it — the response indicated the backend did not consume the body. Use the same prepend-then-clear sequence as the exception branch.

    - Do NOT change the heartbeat behaviour (a heartbeat is just another event for `last_inflight` purposes; that is acceptable — a redelivered heartbeat is harmless on the backend).
    - Do NOT introduce a watermark / backend-ack protocol — ISS-06 lists that as an alternative but the in-flight prepend is the cheaper fix and aligns with current backend semantics.
    - Keep the existing `pending_after_break` semantics: pending is replayed at the start of every new `body_iter`.
