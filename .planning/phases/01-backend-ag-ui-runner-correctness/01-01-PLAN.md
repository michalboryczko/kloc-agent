<objective>
Fix two cooperating bugs in `src/api/internal.py:_dispatch_frame` that violate AG-UI lifecycle ordering and corrupt active-run tracking during run handover.

ISS-01 (Critical): currently, when a `RUN_STARTED` frame arrives for a session that has a pre-RUN_STARTED orphan buffer, the buffered frames are flushed to the bus BEFORE the `RUN_STARTED` frame itself is published (line 162). Subscribers see `[buffered..., RUN_STARTED, ...]` instead of `[RUN_STARTED, buffered...]`, violating the AG-UI lifecycle invariant that `RUN_STARTED` must be the first event a subscriber observes for a run. This is the primary suspect for the resume / cursor-replay regression.

ISS-04 (High): the `RUN_FINISHED`/`RUN_ERROR` branch pops `active_by_session[session_id]` unconditionally. If a fresh run B's `RUN_STARTED` arrived in a separate ingress request between the prior run A's `bus.publish(RUN_FINISHED)` and this pop, the pop wipes B's mapping. B's first intermediate frame then gets buffered as a (now spurious) orphan.

Both bugs live in the same function and share the same test surface, so they ship in one plan.

Purpose: AG-UI lifecycle ordering is a contract subscribers rely on for cursor-replay and resume; run-id mapping is the routing key for every non-lifecycle frame.
Output: corrected `_dispatch_frame` + regression tests that would have caught each bug.
</objective>
