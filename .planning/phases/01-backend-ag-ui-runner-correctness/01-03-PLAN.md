<objective>
Fix ISS-03 (High): `runner/hooks/audit.py:AuditHookSender.stop()` cancels the `_after_worker` task without draining `_after_queue` (max 256). Every graceful shutdown — including warm-idle eviction — drops every queued AfterToolCall payload, losing up to 256 `tool_call.completed` audit rows per runner exit. This is the source of the audit-completeness gap.

Fix: drain the queue first. Loop `_after_queue.get_nowait()` and `await self._post(payload, "AfterToolCall")` for each, bounded by the per-request `HOOK_DEADLINE_S` timeout on `self._http`. Then cancel the worker (now idle).

Purpose: audit completeness is a hard milestone goal — every tool call that completes must produce a `tool_call.completed` row.
Output: drain-then-cancel `stop()` + unit regression test asserting `_post` is called once per queued payload before the worker is cancelled.
</objective>

    - Given a populated `_after_queue` with 3 payloads and a stubbed `_post` that records calls, when `stop()` is awaited, `_post` is invoked exactly 3 times with `event_name == "AfterToolCall"` and with the 3 payloads in FIFO order
    - When `_post` raises on a payload, `stop()` logs and continues draining the remaining payloads (does NOT abort the drain on the first failure)
    - After `stop()` returns: `_after_queue.empty()` is True; `_after_worker.done()` is True (cancelled); `_http` is None (aclosed)
    - When `_after_queue` is empty at the time `stop()` is called, `stop()` cancels the worker and aclose's `_http` without invoking `_post`
    - The drain happens BEFORE the worker is cancelled (the cancel-then-await sequence remains, but only after the drain loop completes)
  </behavior>
  <action>
    In `runner/hooks/audit.py:AuditHookSender.stop`, restructure the method body to:
    1. If `self._http is not None and self._after_worker is not None`: drain `self._after_queue` with a bounded loop. While True, try `payload = self._after_queue.get_nowait()`; on `asyncio.QueueEmpty`, break. For each payload, `try: await self._post(payload, "AfterToolCall")` and on any `Exception` `log.exception("audit.after_post_failed_during_drain")` and continue (do not re-raise). Do not bound the loop with a wall-clock deadline — the per-request timeout on `self._http` (HOOK_DEADLINE_S = 2.0) already bounds total time at `2.0 * len(queue)` worst case, which for the 256-cap queue is 512s; this is acceptable per ISS-03's "bounded by HOOK_DEADLINE_S * len(queue)" guidance.
    2. After the drain, cancel `self._after_worker` and await it as today (preserve the existing `try/except (asyncio.CancelledError, BaseException): pass` shape).
    3. After the cancel, `if self._http: await self._http.aclose(); self._http = None` as today.

    Order constraints:
    - The drain MUST occur before the worker is cancelled (so the queue is not racing the worker's own `get`).
    - The drain MUST occur before `self._http.aclose()` (otherwise `_post` would fail on a closed client).
    - Preserve idempotency: a second call to `stop()` must not raise (drain over an empty queue + cancel of a done task + None http are all already idempotent).

    Do NOT add a separate `flush()` method. Keep all behaviour inside `stop()` per the ISS-03 recommended option.

    In `runner/__main__.py`: confirm `await audit_sender.stop()` is awaited in the `finally` (it already is at line 144). No change required unless the executor finds the ordering accidentally changed. Do not modify any other line in `__main__.py` in this plan.
