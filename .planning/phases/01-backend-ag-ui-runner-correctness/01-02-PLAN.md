<objective>
Fix ISS-02 (High): in `src/api/stream.py:stream_post`, `_persist_events` is unconditionally spawned on every POST. The existing `app.state.persist_tasks` is a `set` used only for shutdown drain — there is no `(session_id, run_id)` lookup. Two concurrent `POST /v1/sessions/{id}/stream` calls for the same in-flight run double-subscribe the event bus, each create a persister, each appends every runner-emitted event to the execution ring (double-counted), and race two `message_uuid` dicts on the first delta (which then competes with `MessageRepo._MAX_SEQ_RETRIES`).

Fix: key `persist_tasks` by `(session_id, run_id)` as a dict. If a live persister already exists for that key, skip creation and subscribe a fresh SSE generator onto the same bus topic instead. The SSE side already supports multiple subscribers per topic via `event_bus.register` + `event_bus.consume`.

Purpose: correctness of cursor-replay (`execution_registry.events` is the replay source — duplicates corrupt `last_event_id` semantics) and prevention of duplicate message-seq inserts.
Output: dedup'd persister spawn + unit and integration regression tests covering the double-spawn path.
</objective>
