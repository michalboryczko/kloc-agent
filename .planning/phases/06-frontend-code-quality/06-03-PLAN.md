# Phase 6 Plan 03: AbortController propagation + dedup + clear error surface

## Objective

Resolve FE-DATA (4 findings in `docs/reviews/frontend/data-fetching.md`):

1. Plumb `AbortSignal` through every `frontend/src/lib/api.ts` call
   (D-1).
2. Wire React-hook-managed `AbortController` lifecycles so the underlying
   fetch is actually aborted on unmount / nav (D-1).
3. Dedup: when a hook re-fires while a prior fetch is in flight, abort
   the prior and proceed with the new one (D-2 spirit, scoped).
4. Differentiate error types: separate `AbortError` from network errors
   from HTTP 4xx/5xx in the returned promise (D-3 spirit).

D-2 (full SWR adoption) and D-4 (pagination UI) remain deferred — they
are scope-creep at v1. See `docs/reviews/frontend/data-fetching.md`.

<task id="1" type="auto">
  <name>Add ApiError + AbortSignal threading to api.ts (D-1, D-3)</name>
  <files>frontend/src/lib/api.ts</files>
  <behavior>
  Every fetch wrapper accepts an optional `{ signal?: AbortSignal }` parameter.
  The `jsonOrThrow` helper distinguishes:
  - `AbortError` → rethrown as-is (so callers can ignore on unmount).
  - HTTP non-2xx → throws `ApiError` with `status` and `body` fields.
  - Network failure / DNS error / disconnect → throws `NetworkError` (a subclass).
  </behavior>
  <implementation>
  - Define `class ApiError extends Error { constructor(public status: number, public body: string, message: string) }`.
  - Define `class NetworkError extends Error {}`.
  - Update `jsonOrThrow<T>(res: Response)` to throw `ApiError(res.status, body, …)` on non-ok.
  - Add helper `safeFetch(url, init)` that wraps `fetch` with a try/catch — non-Abort errors become `NetworkError`. `AbortError` rethrown.
  - Update each `listSessions`, `getSession`, `listMessages`, `createSession`, `closeSession` to accept `signal?: AbortSignal` (last positional optional arg, or second arg via options object — keep existing options-object signatures by extending with `signal`).
  - Pass `signal` through to `fetch` via the second-arg init.
  </implementation>
  <verification>
  - `cd frontend && npx tsc --noEmit` passes.
  - `cd frontend && npm test` still passes (existing tests don't touch api.ts).
  </verification>
  <done-when>
  All five API helpers accept `signal`; `ApiError` and `NetworkError` are exported; `AbortError` propagates unchanged.
  </done-when>
</task>
