# Phase 6 Plan 02: SSE lifecycle + debug-gated body dump + input-trust + CSRF posture

## Objective

Resolve FE-ROUTES (5 findings in `server-and-routes.md`) and FE-SEC
(4 findings in `security.md`). Concretely:

1. Validate the agent-proxy POST body shape (`RunAgentInput`-ish) and
   return 400 on malformed input (SEC-2 surface).
2. Gate the `console.warn` body-keys dump behind `NEXT_PUBLIC_DEBUG_HTTP`
   (S-3, SEC-3).
3. Add `runtime`/`dynamic`/`fetchCache` route exports for the SSE-producing
   routes (S-2).
4. Wrap upstream fetch in a request-scoped timeout + sanitized error
   surface (S-4).
5. Document the CSRF posture in `frontend/docs/csrf.md` (SEC-1 disposition).
6. Add a regression test for the input-trust validator using Node's built-in
   test runner (no new test framework dependency).

<task id="2" type="auto">
  <name>Wire validator + debug-flag + timeout + sanitized error into agent-proxy/route.ts (S-2, S-3, S-4, SEC-2, SEC-3)</name>
  <files>frontend/src/app/api/agent-proxy/route.ts</files>
  <behavior>
  The route should:
  1. Declare `runtime = "nodejs"`, `dynamic = "force-dynamic"`, `fetchCache = "force-no-store"` exports.
  2. Parse JSON body.
  3. Call `validateIncomingBody`; on failure, return 400 with the reason.
  4. Resolve session_id; on failure, gate the diagnostic dump behind `NEXT_PUBLIC_DEBUG_HTTP === "true"` and log only the *keys* (never the values) of state/forwardedProps.
  5. Build the `RunAgentInput` envelope.
  6. Fetch upstream with `AbortSignal.any([req.signal, AbortSignal.timeout(30_000)])`.
  7. On upstream failure or timeout, log structured server-side (status + url + brief error) and return a sanitized message to the browser (no raw backend body text echoed back into the UI).
  </behavior>
  <implementation>
  - Add `export const runtime = "nodejs"; export const dynamic = "force-dynamic"; export const fetchCache = "force-no-store";` near the top.
  - Replace inline `IncomingMessage`/`IncomingBody` types with imports from `./validation`.
  - Replace ad-hoc body parsing with `validateIncomingBody(parsed)`.
  - Replace `console.warn("[agent-proxy] no session_id...", { state: body.state, forwardedProps: body.forwardedProps })` with a debug-gated block that logs only `Object.keys(...)`.
  - Use `AbortSignal.any([req.signal, AbortSignal.timeout(30_000)])` for the upstream fetch.
  - On upstream non-ok: log structured (`console.error("[agent-proxy] upstream failed", { status, url: url.toString() })`), discard the upstream body, and return `Response.json({ error: "agent-proxy: backend rejected", status: upstream.status }, { status: upstream.status })`.
  - Catch `AbortError` from the timeout case and return 504.
  </implementation>
  <verification>
  - `cd frontend && npx tsc --noEmit` passes.
  - `cd frontend && npm run build` succeeds.
  </verification>
  <done-when>
  Route exports the three runtime hints, validates body shape, debug-gates the warn, applies a 30s timeout, and returns sanitized errors.
  </done-when>
</task>
