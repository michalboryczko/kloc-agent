## Description

Two distinct runner ↔ backend communication bugs survive the PGMQ inbox migration. They share one user-visible symptom ("the chat freezes") but have independent root causes and independent fixes. Both must close in this task because they are the two halves of "the runner cannot talk".

### Bug 1 — warm-runner reuse self-blocks for the full warm-idle window

`RunnerRegistry.get_or_spawn`, when reusing a warm `RegistryEntry`, calls `entry.warm_idle.await_kill_in_flight()` at `src/runner_mgmt/registry.py:222`. That method awaits `self._task`, which is the warm-idle countdown sitting in `await asyncio.wait_for(self._activity.wait(), timeout=warm_idle_s)`. The activity event is only set by `WarmIdleManager.on_user_message()`, which `stream_post` calls *after* `get_or_spawn` returns. The handler self-blocks until the warm-idle timeout expires (300 s default), the manager terminates the container, and a fresh spawn drains the message.

**Fix:** Split `WarmIdleManager` lifecycle into countdown vs terminating phases. Introduce `self._killing: bool` set True only after the activity-wait raises `TimeoutError` and the manager begins calling `Runner.terminate(handle)`. `await_kill_in_flight` only awaits the task when `_killing` is True; returns immediately during the countdown phase. Additionally, `RunnerRegistry.get_or_spawn` calls `entry.warm_idle.on_user_message()` *before* `await_kill_in_flight()` so the countdown is cancelled atomically as part of the reuse decision.

### Bug 2 — oversized AG-UI frame poisons the runner channel

`src/api/internal.py:197` caps each JSONL line at `MAX_LINE_BYTES = 1 MiB`. Oversized AG-UI events (typically `ToolCallResult` carrying `kloc_flows` / `file_read` output) receive HTTP 413. `runner/channel.py:_stream_outbound` reacts to any 4xx/5xx by prepending every frame from the failed attempt back into `pending_after_break` and reconnecting; the next attempt re-yields the same oversized frame first, hits 413 again, ad infinitum. The persister stops seeing events, hits its 60 s idle budget, the heartbeat watcher fires `runner_heartbeat_lost`, the runner is killed.

**Fix:** Three layers. (a) Raise the backend cap to `MAX_LINE_BYTES = 16 MiB`. (b) Enforce a runner-side cap `RUNNER_MAX_FRAME_BYTES = 15 MiB`; oversized payloads route through the existing `ArtifactRegistered` HMAC webhook + S3 path and the AG-UI frame is rewritten to a `ToolCallResult` whose body references the artifact id. (c) Split `_stream_outbound` failure handling: transient (`httpx.TransportError`, 408, 5xx) keeps prepend-and-retry; permanent (any other 4xx) drops the offending frame, emits a single `RUN_ERROR` AG-UI event with `cause: "frame_rejected"` and the upstream status code, continues draining.

The two cap constants live in a new `src/shared/transport_limits.py` so they cannot drift.

### Audit + observability

A new audit event `runner_channel_frame_rejected` is appended to the locked vocabulary in `src/db/models.py:AuditEventType`. Payload: `{runner_id, run_id, cause, upstream_status, byte_size}`. OTel counter `kloc_agent.runner.frame_rejected_total{cause=...}` and histogram `kloc_agent.runner.frame_bytes` are emitted from the JSONL ingress at the cap-check boundary.

## Deliverables

1. **`src/shared/__init__.py`** + **`src/shared/transport_limits.py`** — single source for `MAX_LINE_BYTES = 16 * 1024 * 1024` and `RUNNER_MAX_FRAME_BYTES = 15 * 1024 * 1024`. Imported by `src/api/internal.py` and `runner/channel.py`. Module is import-safe for both backend and runner.
2. **`src/runner_mgmt/warm_idle.py`** — `WarmIdleManager` gains `self._killing: bool`. `_await_idle_then_kill` sets `self._killing = True` after the activity-wait raises `TimeoutError` and before the `terminate(handle)` call. `await_kill_in_flight` returns immediately when `self._killing is False`. Existing public API surface unchanged.
3. **`src/runner_mgmt/registry.py`** — `RunnerRegistry.get_or_spawn`, in the warm-entry-found branch, calls `entry.warm_idle.on_user_message()` before `entry.warm_idle.await_kill_in_flight()`. Concurrency invariants near `_spawn_locks` preserved.
4. **`src/api/internal.py`** — `MAX_LINE_BYTES` imported from `src/shared/transport_limits.py`. Emits `runner_channel_frame_rejected` audit + OTel counter on cap rejection. 413 response body carries a structured `{"reason": "frame_oversized", "byte_size": N, "cap": MAX_LINE_BYTES}` so the runner's error path can distinguish.
5. **`runner/channel.py`** — `RUNNER_MAX_FRAME_BYTES` imported from `src.shared.transport_limits` (or duplicated read-only constant if cross-package import is undesirable). New helper `_offload_oversize_frame(frame)` short-circuits any frame whose serialised length exceeds the cap into the artifact-upload path; the enqueued frame is rewritten to reference the returned `artifact_id`. `_stream_outbound` splits 4xx into permanent vs transient:
   - Transient: `httpx.TransportError`, response status 408, 500-599 → existing prepend-and-retry.
   - Permanent: response status in {400, 413, 414, 415, 422} → drop offending frame, emit one `RUN_ERROR` AG-UI event with `cause="frame_rejected"` and `upstream_status=<status>`.
6. **`src/db/models.py`** — `AuditEventType` Literal gains `"runner_channel_frame_rejected"`. The docstring on the Literal records the new event semantics.
7. **`docs/usdl/composition.xml`**:
   - `cmp.backend.runner-mgmt` structure block no longer lists `inbox` as a `RegistryEntry` field.
   - New rule under `cmp.backend.runner-mgmt`: *"`get_or_spawn`, when reusing an existing entry, calls `warm_idle.on_user_message()` before `await_kill_in_flight()`."*
   - New constraint `con.warm-idle-cancel-before-reuse`.
   - `con.channel-replay-on-failure` replaced by `con.channel-replay-on-transient` + `con.channel-drop-on-permanent`. The replay-everything wording is gone.
   - New rule under `cmp.runner.channel`: *"The runner refuses to enqueue any JSONL line larger than `RUNNER_MAX_FRAME_BYTES`; oversized payloads are routed through the artifact-upload path."*
8. **`docs/usdl/interfaces.xml`** — `ifc.ingest-runner-events.failure-mode condition="oversized-frame"` gains `caller-action="drop-and-emit-run-error"`; the 16 MiB cap is named in the contract intent.
9. **`docs/usdl/topology.xml`** — `top.com.runner-to-backend-events` note documents the 16 MiB cap explicitly.
10. **`docs/tasks/fix-runner-inbox/README.md`** — adds a status note that the "second message does nothing" symptom now has a second (post-PGMQ) root cause covered by T01, so the prior task is not misread as the active fix.
11. **Tests:**
    - `tests/unit/test_warm_idle_phases.py` — drives `WarmIdleManager` through countdown vs terminating; asserts `await_kill_in_flight` blocks only during terminate.
    - `tests/unit/test_registry_warm_runner_reuse_ordering.py` — asserts `on_user_message()` called before `await_kill_in_flight()` in the reuse branch.
    - `tests/integration/test_warm_runner_second_message.py` — real PGMQ round-trip; turn 1 → `RUN_FINISHED` → turn 2; asserts the second `pgmq.send` lands in `pgmq.q_inbox_<slug>` within 500 ms.
