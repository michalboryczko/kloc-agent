## Description

The runner-side agent has unconstrained access to MCP tools served by `kloc-intelligence`. Two tools in particular — `file_read` and `kloc_flows` — can return many MiB of data inline, eating runner memory and the model's context window for no analyst value. The platform's only existing policy lever (`KLOC_DENY_TOOLS`) is binary by tool name; there is no per-argument inspection. The agent never sees a "file too large" hint, so it has no incentive to call the tool with a byte range or use `kloc_flows`-style summaries instead.

### The policy layer

Extend `Policy.decide` in `src/hooks_audit/policy.py` to consult a new `KLOC_TOOL_LIMITS` setting (JSON-typed) on `Settings`. For `BeforeToolCall` events, look up a `ToolPolicyEvaluator` by `tool_name` in a registry (`EVALUATORS`); when present, `evaluator.evaluate(args)` returns `PolicyDecision | None` (None → allow). On deny, the response carries `{"decision": "deny", "reason": "tool_limit:<kind>", "hint": "<actionable message>"}`.

The runner's existing `BeforeToolCall` handler already wires `event.cancel_tool = reason` and emits a `ToolCallDenied` AG-UI event. T02 extends that event's `value` dict with an optional `hint: str` field; the runner reads `response["hint"]` and threads it through `_emit_tool_call_denied`. The agent observes the hint as the tool result and self-corrects (e.g. re-calls `file_read` with `start_line` / `end_line`, or uses `kloc_flows` instead).

### The evaluators

Two evaluators ship in v1, registered under `src/hooks_audit/evaluators/`:

- `FileReadEvaluator` — reads `path` from args, optional `start_line` / `end_line` / `max_bytes`; calls `stat_client.stat(path)` for the byte size; compares against `KLOC_TOOL_LIMITS["file_read"]["max_bytes"]`. Cap exceeded → deny with a hint that names the actual size and suggests `start_line` / `end_line` or `kloc_flows`.
- `KlocFlowsEvaluator` — reads `depth` / `limit`; when `require_bounded=true` and both are absent → deny with a hint that suggests `kloc_flows(depth=2)`.

### The stat client

A new module `src/hooks_audit/stat_client.py` issues the HTTP stat call against `KLOC_INTELLIGENCE_STAT_URL` (defaulting to `KLOC_MCP_URL` with the path replaced by `/v1/file_stat`). Timeout 500 ms, single-attempt. On any exception logs a warning, increments the OTel counter `kloc_agent.policy.stat_unavailable_total`, returns `None`. The cap is best-effort guidance, not a security boundary — the hard safety net is T01's channel-level cap, so `allow` on stat-call failure is correct.

### The kloc-intelligence side

A private HTTP endpoint `GET /v1/file_stat?path=<path>` returning `{"exists": bool, "size_bytes": int, "is_file": bool}` is added to kloc-intelligence's `mcp-server-http` ASGI app on a non-MCP path. The Open Items section of the spec asks whether `file_stat` should ALSO be exposed as an MCP tool so the agent can pre-flight stats; the recommendation is yes, but the kloc-intelligence side of that decision is tracked as a sibling task in the kloc-intelligence repo. T02 lands the backend-side consumer and the HTTP endpoint; the MCP-tool exposure (if approved) lands separately.

## Deliverables

1. **`src/hooks_audit/evaluators/__init__.py`** — exposes `EVALUATORS: dict[str, ToolPolicyEvaluator]` (the registry) and the `ToolPolicyEvaluator` Protocol (`runtime_checkable`, one method `evaluate(args: dict) -> PolicyDecision | None`).
2. **`src/hooks_audit/evaluators/file_read.py`** — `FileReadEvaluator` per the Description above. Pure async function shape so the stat call is awaitable; the registry entry is the evaluator instance.
3. **`src/hooks_audit/evaluators/kloc_flows.py`** — `KlocFlowsEvaluator` per the Description above. Synchronous (no I/O).
4. **`src/hooks_audit/stat_client.py`** — single async function `stat(path: str) -> FileStat | None` (`FileStat = TypedDict({"exists": bool, "size_bytes": int, "is_file": bool})`). `timeout=0.5`. Single httpx call; no retry. Boots a module-level `httpx.AsyncClient` lazily.
5. **`src/hooks_audit/policy.py`** — `Policy.decide` rewritten to:
   1. Short-circuit non-`BeforeToolCall` events to `allow` (unchanged).
   2. Look up an evaluator by `tool_name` in `EVALUATORS`; if present, `await evaluator.evaluate(args)`; if the evaluator returns a `PolicyDecision`, return it.
   3. Fallback to the existing `KLOC_DENY_TOOLS` check (lowest precedence). Deny set membership returns `{"decision": "deny", "reason": "test-deny:<tool>"}`.
6. **`src/settings.py`** — `Settings` gains two fields:
   - `tool_limits: ToolLimitsConfig` parsed from `KLOC_TOOL_LIMITS` (JSON env var; empty dict default). Typed as a Pydantic model so malformed JSON fails fast at boot.
   - `intelligence_stat_url: str` parsed from `KLOC_INTELLIGENCE_STAT_URL`; default derived from `kloc_mcp_url` by replacing the path with `/v1/file_stat`.
7. **`runner/hooks/audit.py`** — `_emit_tool_call_denied` accepts an optional `hint: str | None = None` and includes it under `value.hint` when non-None. `before_tool_call`, after parsing the response, passes `response.get("hint")` through.
8. **`.env.example`** — documents both new settings with recommended starting values (`KLOC_TOOL_LIMITS = '{"file_read":{"max_bytes":262144},"kloc_flows":{"require_bounded":true,"max_results":200}}'`, `KLOC_INTELLIGENCE_STAT_URL = http://kloc-intelligence:8765/v1/file_stat`) plus inline comments explaining the rationale.
9. **kloc-intelligence side: `/v1/file_stat` endpoint** — landed as a sibling change in the kloc-intelligence repo. Out-of-scope-for-this-repo deliverable but tracked: a stub fixture server in `tests/fixtures/intel_stat_server.py` lets the kloc-agent integration tests run without the real kloc-intelligence container.
10. **`docs/usdl/composition.xml`**:
    - `cmp.backend.hooks-audit` structure block names `Policy`, `EVALUATORS`, `stat_client.py`, `evaluators/file_read.py`, `evaluators/kloc_flows.py`.
    - New constraint `con.tool-policy-argument-aware`: *"`Policy.decide` consults a per-tool `ToolPolicyEvaluator` registry when `event_type == BeforeToolCall`; the evaluator inspects `args` and may deny with a reason and a hint."*
    - New constraint `con.policy-stat-best-effort`: *"Stat-call failure returns `allow`; the cap is guidance, not a security boundary."*
11. **`docs/usdl/interfaces.xml`** — new contract `ifc.intel-stat` (provider `top.kloc-intelligence`, consumer `top.backend`); the existing `BeforeToolCall` webhook contract is extended with the optional `hint: str` field on the deny response.
12. **`docs/usdl/topology.xml`** — new communication edge `top.com.backend-to-intel-stat` carrying `ifc.intel-stat`.
13. **Tests:**
    - `tests/hooks_audit/test_policy_tool_limits.py` — the 12 cases listed under verification (file_read under cap, over cap, with byte-range, missing path, stat timeout; kloc_flows unbounded, with depth, with limit; unknown tool; deny-set precedence; malformed JSON; empty config).
    - `tests/unit/test_stat_client.py` — timeout returns None + counter incremented; 200 returns the parsed shape; 404 returns `{exists: false, size_bytes: 0, is_file: false}`.
    - `tests/integration/test_file_read_denial.py` — end-to-end with the fixture stat server; agent calls `file_read` against a 5 MiB fixture; FE receives `ToolCallDenied` with the hint; the agent's next turn does not retry the same call.

## Dependencies

- **T01** is *not* a hard dependency. T02 ships a policy layer that stops most oversized calls before they happen; T01 ships the channel-level safety net. Either can land first. If T02 lands first, the worst case for an oversized call slipping through the policy (e.g. an unknown tool) is the existing 1 MiB channel-poisoning bug — same as today, no regression.
- No new external infra. The kloc-intelligence container is already in the operator's compose stack; the new `/v1/file_stat` endpoint is a single ASGI route addition.
- The HMAC webhook flow `runner → /v1/webhooks/runners/{id}/events → src/hooks_audit/policy.py` is unchanged; T02 only changes the body of `Policy.decide`.

## Notes

- The Open Items section of `docs/specs/tool-result-size-limits.md` lists five PM decisions: (1) `file_stat` as MCP tool yes/no, (2) ship-with-defaults vs ship-empty, (3) hint copy review, (4) `<rule>` under `beh.ask-assistant`, (5) audit payload schema versioning. Verification check 9 hits (5) implicitly (precedence ordering needs to match docs). Checks 21 hits (1). Check 18 reflects (2)'s default. The other two are spec-only and do not gate code-level verification.
- The deny-set precedence question (verification check 9) is one of the few places where the spec, the deliverables, and the verification can disagree. The recommended resolution is: evaluator-first, deny-set as the lowest-precedence fallback. If the team chooses deny-set-first instead, edit the deliverables and the spec to match before the task closes. Do not let the code drift from the spec.
- The fixture stat server (`tests/fixtures/intel_stat_server.py`) is the contract source of truth until the real kloc-intelligence endpoint lands. Keep its response shape and HTTP status semantics aligned with `docs/usdl/interfaces.xml:ifc.intel-stat` — when the cross-repo change lands, the fixture is what kloc-intelligence is contracting to.
- This task is the natural home for a follow-up "per-call concurrency budget" or "tool-call rate limit" evaluator. Those are explicit non-goals for T02 but the registry shape (`ToolPolicyEvaluator` Protocol) is designed so adding them is a single-file change.
