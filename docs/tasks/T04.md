## Description

The runner today exposes exactly one subagent — a `summarizer` hardcoded in `runner/agent_factory.py:133-142`. Every change to subagent persona, scope, or addition of a new specialist requires a Python edit + image rebuild + redeploy. T04 replaces that hardcoded list with a filesystem autoregistry that mirrors the existing skills mechanism: drop an `AGENT.md` under `agents/<name>/`, restart the runner, the orchestrator picks it up as an agents-as-tools subagent.

Why agents-as-tools (not graph / swarm): a Strands `Agent` placed in another agent's `tools=[...]` is auto-wrapped as a tool whose call goes through the same `BeforeToolCallEvent` / `AfterToolCallEvent` pathway as MCP tools. The existing audit hook in `runner/hooks/audit.py` therefore covers subagent delegation with zero changes — verified in `docs/research/01-strands-minimal.md:191`. Graph/swarm would route through `Before|AfterMultiAgentInvocationEvent` and `Before|AfterNodeCallEvent`, requiring a parallel audit registration path. Defer that migration until ≥3 fixed-topology subagents demand deterministic routing (`docs/research/01-strands-minimal.md:115`).

Why mirror `skills/` exactly (named volume + init sidecar + read-only mount): the `skills/` path already proves the pattern works end-to-end through aiodocker. A bind-mount of `./agents/` from compose would hit the same backend-container vs host-daemon path-resolution mismatch documented in `src/runner_mgmt/hydrate.py:117-124`. Doing it differently here would be a one-off for no benefit.

### File format

`agents/<name>/AGENT.md`. The `<name>` directory segment is informational only; the canonical name comes from frontmatter so a directory rename does not silently re-key the subagent.

```markdown
---
name: summarizer
description: "Produce a 3-bullet executive summary of code-intelligence results. Cite symbol FQNs verbatim."
---

You receive raw code-intelligence results and produce a 3-bullet
executive summary. Cite symbol FQNs verbatim. Do not editorialise; do
not invent symbols not present in the input.
```

Frontmatter contract (Pydantic `AgentSpec`):
- `name: str` — lowercase-hyphen, 1–64 chars, `^[a-z][a-z0-9-]*$`. Becomes `Agent.name` and therefore the tool name the orchestrator's LLM uses to invoke it. **Must be unique across the agents directory AND must not collide with an MCP tool name** (collision → load-time error, file skipped, audit-logged).
- `description: str` — 1–1024 chars. Appended as the tool description the orchestrator's LLM sees when deciding whether to delegate.

The markdown body (everything after the closing `---`, leading whitespace stripped) becomes the subagent's `system_prompt`. The author owns it end-to-end — no template prefix or suffix is injected (skills already inject a generic skills-prompt prefix; subagents are tighter specialists and a generic prefix would dilute focus).

### Tool surface for subagents

Each subagent receives the same toolset as the orchestrator: `[*mcp_tools, file_read]`. Rationale:
- A specialist that cannot reach kloc-intelligence MCP is no more useful than a model call wrapped in a function — the value of a subagent is **isolated context** for the same toolset, not a different toolset.
- `file_read` is required for skill body progressive disclosure; a subagent that wants to consult a skill must be able to load the `SKILL.md` body.
- Per-subagent tool filtering is out of scope for T04 (frontmatter would need a `tools:` allowlist + a Strands tool registry to filter by name). Tracked as an open item.

### Model

Each subagent inherits the orchestrator's model — one `create_model(...)` call up front, the same `Model` instance passed to every subagent constructor. Rationale: gemini is the only wired provider (`runner/model_factory.py:23`) and there is no cost/latency story today for routing specialists to cheaper models. Tracked as an open item.

### Hook coverage

No hook plumbing changes are required. `_AuditHookProvider` is attached to the orchestrator's per-thread inner agent via `wrap_for_agui(...)` (`runner/agent_factory.py:160-174`). When the orchestrator delegates to a subagent-as-tool, `BeforeToolCallEvent` fires with `tool_use["name"]` set to the subagent's `name` from frontmatter — the existing `AuditHookSender.before_tool_call` (`runner/hooks/audit.py`) posts the webhook unchanged. The subagent itself runs without its own hook registry; tool calls _inside_ the subagent (MCP, file_read) are observed by the orchestrator's hook because the subagent shares the orchestrator's model + tool list (and Strands routes the tool-call lifecycle through the calling agent's HookRegistry).

### Migration of the current `summarizer`

`agents/summarizer/AGENT.md` ships in this task with the exact frontmatter and system prompt currently hardcoded at `runner/agent_factory.py:133-140`. The orchestrator's behaviour for an analyst who asks for a summary is byte-identical to today: same `name="summarizer"`, same system prompt, same delegation pathway. The only observable difference is that the subagent is now load-time-resolved instead of build-time-baked.

### Failure modes (defensive but quiet)

- Missing `agents/` directory → empty subagent list, log `agents.dir_missing`, orchestrator runs with `tools=[*mcp_tools, file_read]` only. Matches the skills loader behaviour at `agentskills/discovery.py:77-79`.
- Malformed YAML / missing required field / invalid `name` regex → skip that file with `log.warning("agents.invalid_spec", extra={"path": ..., "reason": ...})`, continue loading siblings.
- Duplicate `name` across two files → skip the second with `log.warning("agents.duplicate_name", ...)`. The first one to load wins; ordering follows `sorted()` over directory entries for determinism.
- Name collision with an MCP tool → skip the subagent with `log.warning("agents.name_conflicts_with_mcp_tool", ...)` AND emit a `runner_subagent_load_failed` audit event (see Observability) so operators see it. The MCP tool wins because removing a subagent is recoverable; renaming an MCP tool is not.

### Observability

A new audit event vocabulary entry `runner_subagent_load_failed` records per-file load failures (one row per skipped file). Payload: `{"file": "...", "reason": "duplicate_name" | "invalid_spec" | "name_conflicts_with_mcp_tool", "detail": "..."}`. The vocabulary length therefore grows by exactly 1.

A new OTel gauge `kloc_agent.runner.subagents_loaded` is observed once at runner startup with the count of successfully loaded subagents. No per-call counter — subagent invocation already shows up in existing tool-call spans.

1. **`runner/agents_loader.py`** (new) — module exposing:
   - `class AgentSpec(BaseModel)` with fields `name: str`, `description: str`, `system_prompt: str`, `path: Path`. Name validation regex `^[a-z][a-z0-9-]{0,63}$`. Description max length 1024.
   - `def discover_agents(agents_dir: Path) -> list[AgentSpec]` — walks `agents_dir/*/AGENT.md`, parses YAML frontmatter + body, returns `AgentSpec[]` sorted by `name`. Skips invalid files with a `log.warning` per the failure modes above. Returns `[]` on a missing or non-directory path.
   - `def build_subagents(specs: list[AgentSpec], model: Any, tools: list[Any], reserved_names: set[str], audit_emit: Callable[[dict], Awaitable[None]] | None = None) -> list[Any]` — for each spec, instantiates `Agent(model=model, name=spec.name, system_prompt=spec.system_prompt, tools=tools)`. Skips specs whose `name` is in `reserved_names` (MCP tool names) and, if `audit_emit` is provided, calls it with a `runner_subagent_load_failed` payload. Returns the list of constructed subagents.
   - YAML parsing uses `yaml.safe_load`. The frontmatter delimiter is the standard `---\n...\n---\n` pattern; mirror the parser shape used by `agentskills/parser.py`.

## Notes

- **Per-subagent tool filtering (open):** today every subagent gets `[*mcp_tools, file_read]`. A specialist that should only see `kloc_search` would benefit from frontmatter `tools: [kloc_search]`. Adding this needs a Strands tool registry keyed by name + a filter pass in `build_subagents`. Defer until we have a concrete subagent whose context bloat from receiving 22 MCP tools is measurable.
- **Per-subagent model override (open):** frontmatter `model_id:` would let cheap specialists run on a faster/cheaper Gemini variant behind an expensive orchestrator. Defer until cost telemetry justifies the complexity. The current `create_model` signature already accepts an explicit `model_id`, so the loader change would be additive.
- **Sub-agent streaming (open, inherited from `01-strands-minimal.md:204`):** when a subagent runs as a tool, do its intermediate events propagate through the orchestrator's AG-UI stream, or only the final return value? Matters for analyst UX when the subagent itself takes >1 s and produces visible deltas. Empirical test needed once a richer subagent than `summarizer` ships.
- **Migration to Strands `graph` (open):** if/when ≥3 subagents land and routing becomes deterministic, the hook layer needs a parallel `Before|AfterMultiAgentInvocationEvent` registration. Frontmatter could grow a `routes_to: [agent-name]` field then; out of scope for T04.
- **No new env reads on the runner.** The `agents_dir` value flows via the HydrationPayload JSON file, the same channel `skills_dir` uses. The runner image carries no `KLOC_AGENTS_*` env knobs.
- **Why audit a load failure instead of crashing the spawn:** a misformatted AGENT.md authored by an analyst should not take down the runner for every other session pointing at the same `/agents` volume. The audit row makes the failure visible to operators without coupling agent-pack edits to runner uptime. Matches the skills loader's quiet-skip discipline (`agentskills/discovery.py:113-119`).
